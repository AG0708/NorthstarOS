# ADR 0001: Fixed boot extents with generated metadata

- Status: accepted for M0-M1
- Date: 2026-08-11

## Context

The BIOS can read sectors before the kernel has a block driver or filesystem.
Stage 1 must also fit in one boot sector, so parsing a general filesystem there
would add risk without exercising useful kernel behavior. Depending on GRUB,
Limine, or a FAT boot partition would weaken the repository's independent boot
path and introduce extra host tooling.

## Decision

The raw disk image uses fixed, non-overlapping extents generated at build time:

| Payload | Starting LBA | Reserved sectors |
|---|---:|---:|
| Stage 1 | 0 | 1 |
| Stage 2 | 1 | 32 |
| Kernel | 128 | through LBA 4095 |
| Initramfs | 4096 | through LBA 32767 |
| NorthstarFS | 32768 | remainder |

The image builder rejects overflow rather than truncating a payload. It emits a
machine-readable manifest and NASM constants from the same values. Stage 1 loads
stage 2 with BIOS extended reads. Stage 2 loads the kernel through a low-memory
bounce buffer and copies it to its physical load address.

M1 uses a flat kernel binary with a generated byte length and entry address. A
future hardened format may add a versioned header, CRC, and ELF program-header
validation, but those are not silently treated as implemented.

## Consequences

- Early boot is independent of filesystem correctness and optional host tools.
- The runtime filesystem can evolve without changing stage 1.
- The image wastes space between fixed boundaries, which is acceptable for a
  development artifact.
- Replacing a kernel without regenerating metadata is unsafe and therefore the
  image builder is the only supported image-construction path.
